# Architecture

Single activity, Kotlin, Compose for TV. Six dashboard panels use a 1000dp logical canvas scaled to physical width; no 4K wallpaper allocation, runtime blur or network font. The vector mountain backdrop is intentionally simpler than the photographic mockup. App branding comes from installed package icons; demo app tiles use text.

- `data/Models.kt`: immutable entities, configuration, sample states, unit conversion.
- `data/SettingsStore.kt`: private JSON configuration and AES-256/GCM access-token encryption using Android Keystore. Backups are disabled. Tokens never enter saved Compose state, URLs or logs. A saved token cannot be reused for a changed server URL without re-entry.
- `data/AppCatalog.kt`: Leanback/standard launch intent discovery, package visibility queries and HDMI passthrough inputs. No QUERY_ALL_PACKAGES, Play Services or package install permission.
- `ha/HomeAssistantClient.kt`: one authenticated WebSocket. Subscribe before requesting a state snapshot, buffer changes until it arrives, then replay them. Reply IDs correlate commands. Bounded event queue, snapshot/auth/command timeouts, ping frames, jittered exponential reconnect capped at 30 seconds. Invalid authentication stops retries. REST executes services and tests authentication. Standard TLS validation is never bypassed; HTTP is allowed for deliberately configured local servers.
- `LauncherViewModel.kt`: Activity onStart/onStop owns subscriptions. No receiver, alarm, service, worker or wake lock. Forecast refresh runs every 30 minutes only during an active authenticated session. Settings persist independently of HA availability; app launching works offline.
- `camera/CameraPlayer.kt`: optional go2rtc WebRTC with local WebView SDP negotiation, no external scripts or ICE servers; after a timeout, HLS via Media3. The HA camera/stream command obtains an HLS URL when no explicit endpoint is supplied. HA bearer headers are attached only to the exact HA origin, never to arbitrary camera endpoints. Players/WebViews are released on disposal and when stopped. Dashboard previews opt in, with at most two feeds; opening fullscreen disposes previews.
- `ui/`: shared TV surfaces, dashboard, Canvas Sankey and remote-friendly settings. Live HA controls wait for authoritative state updates; mock controls update local demo state only. Unavailable devices are disabled.

Power sensors must report W, kW or MW, not energy in kWh. Configure battery positive = discharging, negative = charging; grid positive = import, negative = export. Node values retain their signs and animation reverses for negative flows. The center is the sum of configured supply sensors; it is not a separately measured whole-home meter. Consumption sensors are independently measured and may not balance due to sample timing or sensor configuration.

Camera compatibility depends on Android WebView codecs, device video decoders, LAN routing and the HA camera integration. This release implements go2rtc's HTTP SDP API, not HA's native camera WebRTC signaling protocol. HA cameras without a configured go2rtc endpoint use HLS. No TURN relay is configured; use HLS if direct LAN ICE connectivity is unavailable.
